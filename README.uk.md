# CCS — процес розробки, що навчається на реальних кейсах

CCS — узгоджений порядок роботи власника проєкту та агента розробки: чітке завдання,
обмежений обсяг змін, перевірений результат і збереження корисних висновків.
Назва CCS збережена як назва підходу; нове розшифрування абревіатури не вводиться.

## Як використовуємо

1. У новому проєкті фіксуємо початковий стан, межі завдання та критерії приймання.
2. Виконуємо короткі перевірки під час виправлень, переглядаємо зміни, потім
   запускаємо фінальні важкі перевірки на стабільній ревізії.
3. Передаємо результат із точним commit, фактичними перевірками та обмеженнями.
4. Якщо виникла неочевидна повторювана проблема, оформлюємо узагальнений кейс:
   симптом → докази → причина або гіпотеза → рішення → правило на майбутнє.
5. Оновлюємо загальне правило й явно переносимо потрібну зміну до проєктних
   інструкцій. Старі рішення не змінюються лише через появу нового документа.

Проєктні WORKFLOW та звіти залишаються у своїх репозиторіях. Тут зберігаємо
переносні правила та уроки без приватних адрес, ключів, журналів чи операційних
ідентифікаторів. Нові кейси додаються під час завершення відповідного завдання;
це не фоновий моніторинг і не дозвіл на довільні зміни інших проєктів.
